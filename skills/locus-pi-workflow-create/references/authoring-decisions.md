# Authoring decisions

Read when a workflow starts accumulating repeated process instructions. This is rationale, not an additional gate or a template for every task.

## D-2026-09-09 — feature ceremony

A feature workflow had repeated repair paragraphs, evidence manifests and copied reports in its prompts. Environment caches also accumulated beside durable evidence. That experience motivated path-based source context, compact briefs and ordinary scratch locations.

Keep the lesson, not the obsolete ceremony: give an agent its task directory and relevant sources; pass complete control handoffs only to their actual consumers. Let reviewers inspect the real diff. Keep dependency caches and temporary output outside durable evidence. Do not rebuild content manifests or copies of the repository merely to review a change.

The former fixed three-round stage loop was one example, not a universal authoring rule. The default now uses adaptive slices with task-derived cumulative and correction bounds. Refusal uses an explicit choice and a failed result; a missing artifact or failed required check cannot become success. Commit only within the task's existing authorization.

Current rules live in [source boundary](source-boundary.md), [adaptive slices](adaptive-slices.md) and the [workflow-create skill](../SKILL.md). Historical implementation details and measurements remain in Git history; stale private file:line citations are not current instructions.

# locus-pi contributor guide

## Purpose

`locus-pi` adds reusable multi-agent workflows to Pi. Users can author a
workflow as readable JavaScript, run and inspect its agents, rerun it, and
route stages through separately configured model roles.

Keep changes aligned with the public product described in [README.md](README.md).
The public package contract is owned by `package.json#pi.extensions`, extension
manifests, packaged workflows, co-located manuals, focused tests, and
`package.json#files`.

## Start here

Use Node.js `>=22.19.0`, Pi `>=0.84.3`, and `ripgrep`.

```bash
npm ci --ignore-scripts
npm run hooks:install
npm run check:fast
```

Locus project state is intentionally local. Run `locus init` to create its
ignored `.locus/` files when needed; `.locus/AGENTS.md` is the registry for
those local surfaces. Do not commit `.locus/`, `.tasks/`, `.pi/`, runtime
output, credentials, or workstation-specific paths.

- `extensions/<name>/` owns one Pi extension and its behavior manual.
- `extensions/_shared/` owns cross-extension code. Read
  `scripts/check-extension-layers.ts` before moving shared modules or changing
  their dependencies.
- `examples/workflows/` owns the packaged workflow catalog and examples.
- `skills/` owns the skills shipped with the package.
- `docs/` owns cross-cutting user guides and references. Keep extension-specific
  behavior in `extensions/<name>/README.md`.
- `scripts/` owns development checks and generators; it is not part of the npm
  package.
- `dist/public-catalogs.json`, the skill-local `references/dsl.md` projection, and the fenced public catalog regions are generated
  by `npm run build:catalogs`. Do not edit them by hand.

Shared modules may not import feature directories. Cross-feature access uses an
explicitly owned facade, and each versioned `globalThis` registry has one owning
module. When extracting a new internal owner, update the ownership ledger in
`scripts/check-extension-layers.ts` and add a negative import test in the same
change.

## Change and documentation rules

Start focused work from current `dev` and open the pull request back into
`dev`; `main` is the stable release branch. Preserve unrelated work and keep
private operator guidance out of Git, pull requests, issues, and package
artifacts.

Do not widen extensions, workflows, dependencies, permissions, or the npm
package boundary without matching tests and documentation. Git is the public
repository inventory; `package.json#files` is the separate npm-package
allowlist.

## Validation

- Run focused tests while editing.
- Run `npm run check:fast` for the local inner loop.
- Run `npm run check` for the canonical deterministic repository gate used by
  CI.
- Run `npm run check:push` before opening or updating a pull request; it adds
  the topology growth ratchet and a dry-run package check.
- Use `npm run sync:pi-host` when intentionally changing the exact Pi
  development baseline, then rerun `npm run check`.

File size is a growth ratchet, not a target. Do not raise an existing topology
exception merely to fit new code.
